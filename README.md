# Care Quotient (CQ) — Care Capacity Index

A city-level index measuring whether urban residents live in places that can provide and sustain care. Published at [petedur.github.io/Care-Quotient---Claude-Code/](https://petedur.github.io/Care-Quotient---Claude-Code/).

## What It Measures

The Care Quotient scores 68 US cities across nine metrics, organized into three pillars:

| Pillar | Weight | Metrics |
|--------|--------|---------|
| Social & Relational Care | 40% | Residential stability (50%), Care nonprofit density (35%), Library density (15%) |
| Institutional Care | 35% | FQHC density (45%), Nursing home capacity (35%), Child care capacity (20%) |
| Economic Access to Care | 25% | Healthcare coverage — Medicaid/CHIP (40%), Housing affordability (35%), SNAP coverage (25%) |

Scores are absolute, not relative. Each metric is benchmarked against a policy-grounded threshold, scored 0–100, and capped at 100. A city's CQ reflects how close it comes to that benchmark — not how it ranks against other cities.

See [docs/methodology.md](docs/methodology.md) for full methodology, benchmark rationale, and known limitations.

## Running the Pipeline

### Prerequisites

```bash
pip install -r requirements.txt
```

You also need:
- A `.env` file with `CENSUS_API_KEY=your_key` ([get one free](https://api.census.gov/data/key_signup.html))
- IRS EO BMF regional CSVs in `Downloaded Data/IRS EO BMF/` ([download from IRS](https://www.irs.gov/charities-non-profits/exempt-organizations-business-master-file-extract-eo-bmf))
- HRSA FQHC site file (`Health_Center_Service_Delivery_and_LookAlike_Sites.xlsx`) in `Downloaded Data/` ([download from HRSA](https://data.hrsa.gov/data/download))
- IMLS Public Libraries Survey files in `Downloaded Data/Public Libraries Survey (PLS)/`

### Full run (all 68 cities)

```bash
python code/pipeline.py
```

### Targeted run (specific cities)

```bash
python code/pipeline.py nyc chicago seattle
```

The pipeline runs collectors → ETL → scoring for the specified cities, then writes `docs/data.js`.

### Factor analysis (validate pillar structure)

```bash
python code/analysis/factor_analysis.py
```

Outputs go to `outputs/`. Review `factor_analysis_weights.json` before adopting any weight changes — empirical and theoretical weights are both shown.

## Geographic Approach

City boundaries are defined using the Census 2020 ZCTA-to-Place relationship file. A ZCTA (ZIP Code Tabulation Area) is assigned to a city if ≥40% of its land area falls within the Census incorporated place boundary. This threshold:
- Eliminates county-sharing inflation (V1/V2 pulled all county data)
- Captures near-boundary ZCTAs that serve city residents (the 40–49% band)
- Uses a consistent geographic definition across all data sources

Cities that are Census Designated Places (CDPs) — currently only Honolulu — fall back to county-based boundaries. See methodology.md for details and the Honolulu caveat.

## Scoring Model

```
metric_score = min(raw_value / benchmark × 100, 100)

pillar_score = weighted average of metric scores within pillar

CQ = 0.40 × Social_Relational + 0.35 × Institutional + 0.25 × Economic_Access
```

All benchmark values and weights are defined in `code/score.py` (`SCORED_METRICS`, `PILLAR_WEIGHTS`). The `factor_analysis.py` script imports these directly — it cannot drift from the scoring model.

Cities with any missing required metric are excluded from all output rather than silently reweighted.
